# Как развернуть всё с нуля

Инструкция по установке VPN на своих серверах: два протокола (AmneziaWG и
Hysteria2) и Telegram-бот, который выдаёт ключи людям из вайтлиста.

Всё описанное ниже проверено на боевой установке из трёх серверов Ubuntu 24.04.

---

## Что получится

| | AmneziaWG | Hysteria2 |
|---|---|---|
| Транспорт | UDP/51820 | UDP/31000 |
| Приложение | AmneziaVPN | HApp |
| Маскировка | обфускация WireGuard | salamander + подмена под сайт |
| Сертификат | не нужен | Let's Encrypt (автоматом) |
| Ключей на человека | сколько угодно, у каждого имя | столько же |

Оба протокола работают одновременно и не мешают друг другу. Лимит ключей общий:
человек сам решает, какой протокол ему нужен.

**Зачем два.** AmneziaWG проще и давно работает. Hysteria2 — запасной вариант на
случай, если AmneziaWG начнут детектить и блокировать: он маскируется лучше и
поднимается на другом порту.

---

## Что нужно заранее

- Один или несколько серверов Ubuntu 24.04 с root-доступом и **белым IP**
- На каждом свободны: UDP/51820, UDP/31000, TCP/80 (нужен разово для сертификата)
- Токен бота от [@BotFather](https://t.me/BotFather)
- Свой Telegram ID от [@userinfobot](https://t.me/userinfobot)

Домен покупать не нужно — сертификат выписывается на имя вида
`203.0.113.10.sslip.io`, которое сервис sslip.io резолвит прямо из IP.

## Шаг 1. AmneziaWG на каждом сервере

Скопировать `install.sh` на сервер и запустить:

```bash
scp install.sh root@СЕРВЕР:/root/
ssh root@СЕРВЕР 'bash /root/install.sh'
```

Скрипт ставит пакеты, генерирует ключи сервера, поднимает интерфейс `awg0`,
настраивает NAT и включает автозапуск. В конце печатает публичный ключ сервера —
он понадобится позже, сохрани.

Проверить, что всё встало:

```bash
awg show awg0                          # интерфейс есть
systemctl is-enabled awg-quick@awg0    # enabled
ip link show awg0 | grep -o 'mtu [0-9]*'   # mtu 1420
dkms status | grep amneziawg           # модуль собран
```

**Три вещи, на которых легко обжечься:**

**MTU обязан быть 1420.** Не 1280 и не меньше. Через туннель ходят крупные
UDP-пакеты — видео по QUIC. Если MTU меньше, они не влезают, а фрагментировать
их нельзя (стоит флаг DF), и сервер молча их выбрасывает. Снаружи это выглядит
так: мессенджеры и сайты работают, а видео не грузится совсем. Диагностируется
командой `tcpdump -i any -nn 'udp port 443'` — видно, как пакет приходит на
внешний интерфейс и не уходит в туннель.

**`amneziawg-dkms` обязателен.** Без него модуль ядра не пересоберётся после
обновления ядра. Сервер перезагрузится, модуля не будет, VPN отвалится у всех
разом. Проверка: `dkms status` должен показывать сборку под текущее ядро.

**Автозапуск не включается сам.** `awg-quick up awg0` поднимает интерфейс
только до перезагрузки. Нужен `systemctl enable awg-quick@awg0` — установщик
это делает, но проверить стоит.

### Пиры должны быть в конфиге, а не только в памяти

`awg set` добавляет пира на живой интерфейс, но после перезагрузки он исчезнет.
Бот пишет пиров и в `/etc/amnezia/amneziawg/awg0.conf`, поэтому они переживают
ребут. Если добавляешь пира руками — не забудь про конфиг.

## Шаг 2. Hysteria2 на каждом сервере

Сначала придумать один пароль обфускации — **общий для всех серверов**:

```bash
openssl rand -base64 24 | tr -dc 'A-Za-z0-9' | head -c 24
```

Затем на каждом сервере:

```bash
scp install-hysteria.sh root@СЕРВЕР:/root/
ssh root@СЕРВЕР 'bash /root/install-hysteria.sh ПАРОЛЬ_ОБФУСКАЦИИ'
```

Скрипт сам определит внешний IP, соберёт из него домен `IP.sslip.io`, получит
сертификат Let's Encrypt и запустит сервис. Пользователей он не заводит — это
делает бот.

Проверить:

```bash
systemctl is-active hysteria-server     # active
ss -ulnp | grep 31000                   # слушает
find /etc/hysteria/acme -name '*.crt'   # сертификат на месте
```

### Прыгающий порт (по желанию)

Если один порт заблокируют, можно раскидать подключения по диапазону:

```bash
PUB=$(curl -4 -s ifconfig.me)
iptables -t nat -A PREROUTING -i ens3 -d $PUB -p udp --dport 20000:30000 \
         -j REDIRECT --to-ports 31000
netfilter-persistent save
```

Диапазон **обязан быть ниже 32768** — выше начинаются эфемерные порты, которые
система раздаёт под NAT существующих VPN-клиентов, и правило начнёт перехватывать
их трафик.

Учти: **многие мобильные клиенты диапазон не понимают.** HApp на Android
разбирает дефис в адресе как границу диапазона и отказывается подключаться. По
умолчанию бот выдаёт ссылки с одним портом; диапазон включается заменой
`hop=False` на `hop=True` в `hy2.build_link`.

## Шаг 3. Бот

Ставится на один сервер, остальными управляет по SSH.

```bash
git clone https://github.com/ROSHCHENKOg/amnezia-bot.git /root/amnezia-bot
cd /root/amnezia-bot
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp .env.example .env
nano .env
```

Заполнить `.env` (подробности внутри файла): токен, свой ID, список серверов,
`HY2_OBFS` — тот самый пароль обфускации.

Настроить беспарольный вход с сервера бота на остальные:

```bash
ssh-keygen -t ed25519 -N '' -f /root/.ssh/id_ed25519
ssh-copy-id -i /root/.ssh/id_ed25519 root@ВТОРОЙ_СЕРВЕР
ssh -o BatchMode=yes root@ВТОРОЙ_СЕРВЕР echo OK   # должно ответить без пароля
```

Запустить как сервис:

```bash
cp amnezia-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now amnezia-bot
systemctl is-active amnezia-bot
```

Раскатать пользователей Hysteria на серверы:

```bash
./venv/bin/python hy2_sync.py
```

Должно вывести `раскатка: server1=OK, server2=OK, ...` по каждому серверу.

## Шаг 4. Проверка

Добавить себя в вайтлист через бота: `/admin` → «Добавить юзера», или
`/add @свой_ник 5`.

Затем в боте: **🔑 Ключ** → выбрать протокол → ввести название.

Проверить, что ключ действительно работает, не полагаясь на слова
пользователей — с любой машины, где есть клиент:

```bash
# Hysteria2: собрать конфиг из выданной ссылки и подключиться
cat > /tmp/c.yaml << 'YAML'
server: 203.0.113.10.sslip.io:31000
auth: ЛОГИН:ПАРОЛЬ
obfs:
  type: salamander
  salamander:
    password: ПАРОЛЬ_ОБФУСКАЦИИ
socks5:
  listen: 127.0.0.1:10808
YAML
hysteria client -c /tmp/c.yaml &
curl --socks5-hostname 127.0.0.1:10808 https://ifconfig.co   # должен показать IP сервера
```

## Что ломается на практике

Собрано по итогам реальной отладки — почти всё здесь стоило нескольких часов.

### Видео не грузится, остальное работает

MTU туннеля меньше 1420. Крупные UDP-пакеты не проходят. Смотри Шаг 1.

Важно: `MSS clamping` тут **не помогает** — он действует только на TCP, а видео
идёт по QUIC поверх UDP. Ровно поэтому «настройка MSS» из советов в интернете
ничего не даёт.

### После перезагрузки VPN не поднялся

Четыре возможные причины, проверять по порядку:

```bash
dkms status | grep amneziawg          # модуль под текущее ядро есть?
systemctl is-enabled awg-quick@awg0   # автозапуск включён?
sysctl net.ipv4.ip_forward            # должно быть 1
grep -c '\[Peer\]' /etc/amnezia/amneziawg/awg0.conf   # пиры в конфиге, не только в памяти?
systemctl is-enabled hysteria-server  # автозапуск Hysteria тоже включён?
```

Последний пункт легко упустить: `systemctl start` поднимает сервис сейчас, но
без `enable` он не переживёт перезагрузку.

### Конфиг разъехался с интерфейсом

`awg set` меняет живой интерфейс, `awg0.conf` — то, что поднимется после
перезагрузки. Если код правит только первое, получается расхождение: новые ключи
пропадают при ребуте, а **отозванные наоборот воскресают**. Проверка:

```bash
echo "интерфейс: $(awg show awg0 | grep -c peer), конфиг: $(grep -c '^\[Peer\]' /etc/amnezia/amneziawg/awg0.conf)"
```

Числа должны совпадать. Если нет — сверь состав по публичным ключам, а не по
количеству: одинаковое число не значит одинаковый набор.

**`awg-quick save` для этого не годится.** Он дописывает поля AWG 3.0
(`AdvancedSecurity`, `ContentPaddingAddition`, `RekeyAfterTime` и другие),
которые `awg setconf` обратно не принимает — конфиг перестаёт подниматься.
Проверено. Правь секции `[Peer]` явно, как это делает `awg_manager.py`.

### Клиент говорит «не работает», а на сервере тишина

Первым делом посмотреть, дошёл ли до сервера хоть один пакет:

```bash
journalctl -u hysteria-server --since '-20 min' -o cat | grep -i ЛОГИН
```

Если записей нет — проблема на устройстве, сервер трогать бесполезно. Самое
частое: **у человека параллельно включён другой VPN**. Android не даёт двум
приложениям держать туннель одновременно, второе просто не стартует. Видно по
адресу в логе: если вместо реального IP там `10.8.0.x`, человек сидит внутри
AmneziaWG и пытается запустить Hysteria поверх него.

### Ссылка не импортируется в мобильный клиент

HApp построен на ядре Xray, и его парсер спотыкается о спецсимволы в адресной
части ссылки. Проверено на практике — ломают:

- **дефис** где угодно до `/?` — читается как диапазон портов
- **точка** в логине — Hysteria читает конфиг через viper, а тот делает из точки
  вложенную структуру, и сервер вообще не стартует

Поэтому в коде: домен в точечной форме (`1.2.3.4.sslip.io`, не `1-2-3-4`), логин
через подчёркивание, пароль только из букв и цифр. Если правишь генератор —
держи это в голове.

### Самоподписанный сертификат

Мобильные клиенты отбрасывают его молча, ещё до попытки подключиться: в
интерфейсе просто «N/A», в логах сервера пусто. Поэтому используется настоящий
Let's Encrypt через sslip.io, а не `insecure: true`.

### Отозвали последний ключ Hysteria — сервис упал

Hysteria не стартует с пустым списком `userpass`. В `hy2._render` на этот случай
подставляется заглушка `_none` со случайным паролем: сервер остаётся живым, зайти
по ней нельзя. Не убирай её.

## Как это устроено внутри

```
Telegram
   │
   ▼
bot.py ──── whitelist.py ──── users.db (SQLite)
   │            │                  ├── whitelist: кто, лимит, назначенный сервер
   │            │                  └── keys: ключи обоих протоколов (колонка protocol)
   │            │
   ├── awg_manager.py ──► awg set + awg0.conf на сервере (SSH)
   │   vpn_uri.py ──────► ссылка vpn:// для AmneziaVPN
   │
   └── hy2.py ──────────► /etc/hysteria/config.yaml на всех серверах (SSH)
                          ссылка hysteria2:// для HApp
```

Ключи обоих протоколов лежат в **одной таблице** `keys`, различаются колонкой
`protocol`. Поэтому лимит, список «Мои ключи» и отзыв работают одинаково для
обоих, без развилок в коде.

Для Hysteria в этой таблице переиспользованы поля: `public_key` — это логин в
`userpass`, `private_key` — пароль, `client_ip` не используется.

`hy2.sync()` собирает всех живых пользователей и раскладывает конфиг по всем
серверам. Вызывается автоматически при выдаче и отзыве ключа, при добавлении и
удалении из вайтлиста. Перезапускает сервис, поэтому активные соединения на пару
секунд рвутся — это нормально.

## Обслуживание

```bash
./venv/bin/python hy2_sync.py                  # перераскатать пользователей
systemctl restart amnezia-bot                  # перезапустить бота
journalctl -u amnezia-bot -f                   # логи бота
journalctl -u hysteria-server -f               # логи Hysteria
awg show awg0                                  # кто подключён по AmneziaWG
```

Сертификаты Let's Encrypt Hysteria продлевает сама, вмешательства не требуется.

## Безопасность

- `.env` в `.gitignore` — там токен бота и пароль обфускации, в репозиторий не попадают
- База `users.db` тоже не коммитится: в ней приватные ключи и пароли всех людей
- SSH-ключи между серверами живут только на серверах
- Если репозиторий публичный — не клади в `.env.example` настоящие IP и ID:
  это прямая наводка на то, что по такому-то адресу стоит VPN
